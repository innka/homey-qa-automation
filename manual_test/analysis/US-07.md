# Analyse de la User Story US-07

## Informations générales

**Titre :** Faire une demande de réservation  
**Priorité :** P1  

**Rôle utilisateur :** Voyageur  

---

# Résumé

En tant que **Voyageur**,  
Je souhaite envoyer une demande de réservation,  
Afin de bénéficier d’un séjour dans un logement saisonnier.

---

# Description fonctionnelle

Un utilisateur connecté en tant que **Voyageur** peut, suite à la consultation d’une annonce correspondant à ses critères, effectuer une demande de réservation pour le logement proposé.

L’annonce doit avoir été créée auparavant par un utilisateur de type **Hôte**.

Un utilisateur non connecté peut commencer la procédure de demande de réservation, mais le système ne doit pas permettre la finalisation de cette demande.

Pour réaliser une demande de réservation, le Voyageur doit renseigner les informations suivantes :

- Date de début de réservation
- Date de fin de réservation
- Nombre de voyageurs
- Message adressé à l’Hôte

Les règles concernant les dates sont les suivantes :

- La date de début doit correspondre à une date disponible dans le futur.
- La date de fin doit correspondre à une date disponible dans le futur et être postérieure à la date de début.

Une période réservée devient indisponible pour les autres réservations.

Après l’envoi d’une demande de réservation :

- L’Hôte reçoit un nouveau message dans sa boîte de réception « Messages ».
- Une nouvelle réservation apparaît dans sa boîte « Réservations ».


---

# Critères d'acceptation analysés

## Scénario 1 : Un Voyageur connecté fait une demande de réservation

### Étant donné

Un Voyageur connecté.

### Quand

L’utilisateur fait une demande de réservation.

### Alors

- Le système crée une nouvelle réservation dans le tableau de bord de l’Hôte correspondant à l’annonce.
- Le système crée un nouveau message dans le tableau de bord de l’Hôte correspondant à l’annonce.

---

## Scénario 2 : Un Visiteur non connecté fait une demande de réservation

### Étant donné

Un Visiteur non connecté.

### Quand

L’utilisateur fait une demande de réservation.

### Alors

- Le système ne donne pas suite à la demande de réservation.

# Préconditions identifiées

| ID | Précondition |
|---|---|
| PRE-01 | Un compte voyageur existe |
| PRE-02 | Un compte hôte existe |
| PRE-03 | Le voyageur peut se connecter |
| PRE-04 | L'hôte a créé une annonce |
| PRE-05 | L'annonce est active |
| PRE-06 | Il y a des dates disponibles |
| PRE-07 | Le voyageur a ouvert la page de l'annonce |
| PRE-08 | Le Voyageur est connecté |

---

# Règles métier identifiées

| ID | Règle métier |
|---|---|
| RM-01 | Seul un Voyageur connecté peut envoyer une demande de réservation |
| RM-02 | Un Visiteur peut commencer la réservation mais ne peut pas la finaliser |
| RM-03 | La date de début doit être disponible et dans le futur |
| RM-04 | La date de fin doit être postérieure à la date de début et disponible |
| RM-05 | Le nombre de voyageurs doit être un entier strictement positif |
| RM-06 | Vérifier l'affichage du message de confirmation |
| RM-07 | Une réservation est créée dans le tableau de bord de l'Hôte |
| RM-08 | Les dates réservées deviennent indisponibles |

---

# Données d'entrée

| Donnée | Description |
|---|---|
| Date de début | Date sélectionnée par le Voyageur pour commencer le séjour |
| Date de fin | Date sélectionnée par le Voyageur pour terminer le séjour |
| Nombre de voyageurs | Nombre entier strictement positif |
| Message | Message envoyé à l’Hôte lors de la demande |

---

# Analyse des risques

| Risque identifié | Impact | Priorité |
|---|---|---|
| Un Visiteur non connecté peut finaliser une réservation | Création de réservations non autorisées | Haute |
| Des dates indisponibles peuvent être sélectionnées | Risque de double réservation | Haute |
| La date de fin peut être antérieure à la date de début | Données de réservation incohérentes | Haute |
| L’Hôte ne reçoit pas la demande de réservation | Perte d’information et de réservation | Haute |
| Les dates réservées restent disponibles | Possibilité de conflit entre réservations | Haute |

---

# Conditions de test identifiées

Les tests devront couvrir les fonctionnalités suivantes :

- Création d’une demande de réservation par un Voyageur connecté.
- Tentative de réservation par un utilisateur non connecté.
- Vérification des champs obligatoires.
- Vérification des règles de validation des dates.
- Vérification du nombre de voyageurs.
- Vérification de l’affichage du message de confirmation.
- Vérification du blocage des dates après réservation.
