# Analyse de la User Story US-08

## Informations générales

**Titre :** Traiter une demande de réservation  
**Priorité :** P2  

**Rôle utilisateur :** Hôte  

---

# Résumé

En tant que **Hôte**,  
Je souhaite accepter ou refuser une demande de réservation,  
Afin de planifier les séjours dans mon logement.

---

# Description fonctionnelle

Un Hôte reçoit les demandes de réservation envoyées par les Voyageurs.

Chaque nouvelle demande reçue doit avoir le statut **NOUVEAU**.

Les informations suivantes doivent être affichées :

- Date de début
- Date de fin
- Voyageurs
- Animaux domestiques
- Total

L'Hôte peut effectuer plusieurs actions sur une demande de réservation :

- Confirmer la réservation.
- Refuser la réservation avec justification.
- Ajouter des frais supplémentaires.
- Ajouter des remises.

Lors de la confirmation d'une réservation, l'Hôte est redirigé vers une page contenant les détails de paiement :

- Nombre de nuits
- Prix par nuit
- Taux d’imposition

Après confirmation de la disponibilité :

- Le statut devient **ATTENTE DE PAIEMENT** dans le tableau de bord de l'Hôte.
- Le statut devient **DISPONIBLE** dans le tableau de bord du Voyageur.

Le Voyageur peut ensuite :

- Payer la réservation via le bouton « Payer maintenant ».
- Annuler la réservation.

Le paiement est possible uniquement avec le mode de paiement **Hors site**.

Avant le paiement, les informations de paiement de l'Hôte doivent être renseignées.

Si les informations bancaires de l'Hôte ne sont pas configurées, le système ne doit pas permettre le paiement.

L'Hôte peut configurer ses informations de paiement via :

**Profil > Paiement**

Les informations nécessaires sont :

- Prénom
- Nom de famille
- Nom de la compagnie
- Numéro d'identification fiscale
- Adresse
- Appt
- Ville
- État
- Code postal
- Mode de paiement : Virement bancaire
- Paiement lors de la réservation

En sélectionnant le mode de paiement **Virement bancaire**, un formulaire supplémentaire apparaît avec :

- IBAN
- Swift
- Nom de banque
- Adresse
- Appt
- Ville
- État
- Code postal

Après l'action « Marquer comme payé » :

- Le statut devient **RESERVE** pour l'Hôte.
- Le statut devient **RESERVE** pour le Voyageur.

# Analyse des risques

| Risque identifié | Impact | Priorité |
|---|---|---|
| Une demande de réservation ne reçoit pas le statut NOUVEAU | Mauvaise gestion du workflow | Haute |
| L'Hôte ne peut pas confirmer ou refuser une demande | Blocage du processus de réservation | Haute |
| Les statuts ne changent pas correctement selon l'action réalisée | Incohérence fonctionnelle | Haute |
| Le paiement est possible sans informations bancaires Hôte | Risque financier | Haute |
| Le paiement ne fonctionne pas avec les informations bancaires configurées | Blocage de réservation | Haute |
| L'action « Marquer comme payé » ne modifie pas le statut | Réservation non finalisée | Haute |

# Conditions de test identifiées

Les tests devront couvrir :

- Affichage d'une nouvelle demande avec le statut NOUVEAU.
- Vérification des informations affichées sur une réservation.
- Confirmation d'une demande par l'Hôte.
- Vérification des changements de statut côté Hôte et Voyageur.
- Refus d'une demande avec justification.
- Ajout de frais supplémentaires.
- Ajout de remises.
- Paiement d'une réservation par le Voyageur.
- Vérification du mode de paiement « Hors site ».
- Blocage du paiement lorsque les informations bancaires de l'Hôte sont absentes.
- Configuration des informations de paiement Hôte.
- Annulation d'une réservation.
- Action « Marquer comme payé » et passage au statut RESERVE.
